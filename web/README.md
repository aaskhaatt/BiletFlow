# BiletFlow web

Web frontend for BiletFlow: the organizer and attendee interfaces.

It talks to the API in [`../backend`](../backend).

Stack: Vite, React, TypeScript, Tailwind CSS, shadcn/ui, React Router, TanStack Query, react-i18next (kk, ru, en). The reasons for each choice are in [`DECISIONS.md`](DECISIONS.md).

## What you need

- Node.js 24 or newer (with npm).
- The backend running locally (next section). It needs Docker and Python 3.12.
- Google Chrome, for the end-to-end tests only.

## 1. Start the backend

From the repository root. On Windows, the venv commands differ: see [`docs/onboarding-dev-b.md`](../docs/onboarding-dev-b.md).

```bash
docker compose up -d postgres
cd backend
python3.12 -m venv .venv               # first time only
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                   # first time only, then set your own SECRET_KEY
alembic upgrade head
uvicorn main:app --reload              # API on http://localhost:8000, docs at /docs
```

Demo data (an admin, an organizer, staff, 10 attendees and 4 events), in a second terminal from `backend/` with the venv active:

```bash
python scripts/seed_demo.py
```

The demo accounts end in `@demo.example.com`. Their shared password is `DEMO_PASSWORD` in `backend/scripts/seed_demo.py`; don't copy it into this folder.

The backend lets the browser call it only from `http://localhost:5173` (its `CORS_ORIGINS`), which is why the web app always runs on that port.

## 2. Start the web app

```bash
cd web
npm install
npm run dev                            # http://localhost:5173
```

The dev server only ever uses port 5173. If something else holds the port, it stops with "Port 5173 is already in use": close the other server and start again.

The API address comes from `VITE_API_URL` and defaults to `http://localhost:8000`. To change it, copy `.env.example` to `.env` and edit it. Everything in `.env` ends up in the browser bundle, so it never holds secrets.

`http://localhost:5173/dev/ui` (dev server only) shows the design tokens, fonts, the base components, the language switcher and a live call to the API.

## API client

The TypeScript types and TanStack Query hooks in `src/api/generated` are generated by [orval](https://orval.dev) from the backend's OpenAPI schema. With the backend running:

```bash
npm run api:gen
```

Another schema address: `OPENAPI_URL=https://.../openapi.json npm run api:gen`.

- Commit the generated files: builds and CI never need a running backend.
- Never edit them by hand: the next `api:gen` overwrites them.
- Components don't import generated hooks. They use our wrappers in `src/api/hooks` (`useEvents`, ...), so a renamed backend operation means one change in one file.
- Every request goes through `src/api/http.ts`: base address, `Authorization: Bearer`, and errors as `ApiError { status, error, message, fields }`. It also has helpers for uploads (`apiUpload`), files such as QR codes and PDFs (`apiBlob`) and CSV exports (`apiCsv`).

## Tests

**Unit and component tests**: `npm test`. Vitest with Testing Library; the API is mocked with MSW (`src/test/msw-server.ts`), and a request without a mock fails the test. Test files sit next to the code: `something.test.ts(x)`.

**End-to-end tests**: `npm run e2e`. Playwright starts the dev server or reuses the one already on 5173. Some tests use the real API, so start the backend first. Local runs use Chrome. GitHub Actions uses Playwright Chromium.

The live session test registers a user. Run it with `BILETFLOW_E2E_LIVE_AUTH=1` against a disposable database with SMTP disabled. The web session workflow supplies this database in CI. Set `PLAYWRIGHT_PORT` and `VITE_API_URL` to test on separate ports, and add the test frontend's origin to the backend's `CORS_ORIGINS`.

## Rules of the codebase

- **Colors, radii and fonts come from tokens only.** The Figma variables are in `src/styles/tokens.css`; Tailwind knows only these colors (`bg-paper`, `text-ink`, `bg-brand`, `bg-status-ok-bg`, ...) and radii (`rounded-sm` 8, `rounded-md` 12, `rounded-lg` 16, `rounded-xl` 20). Text styles: `type-page-title`, `type-event-title`, `type-card-title`, `type-body`, `type-label`, `type-small`. No hex values in components.
- **Base components** are shadcn/ui in `src/components/ui`, restyled with the tokens; buttons and fields are at least 44 px tall. Add new ones with `npx shadcn add <name>`, then restyle them the same way.
- **Icons** come from `src/components/icons.ts`: Lucide icons under their Figma names (`CalendarIcon`, `PinIcon`, ...), 24 px, stroke 2, in the color of the text. Don't import `lucide-react` in pages and components; a new icon goes into that file first.
- **Texts** live in `src/i18n/locales` (`ru.ts` is the reference; `kk.ts` and `en.ts` must have the same keys, or the type check fails). The Kazakh texts still need a check by a native speaker.
- **Errors**: show `t(errorMessageKey(error))`, never the server's `message` (it is English). Every error code has a text in all three languages; a unit test enforces it. For form fields, `applyServerFieldErrors` in `src/lib/form-errors.ts` puts a 422's `fields` onto react-hook-form.
- **Money and time**: `formatKZT` (whole tenge, "Бесплатно" for 0) and `formatEventTime` (always Astana time, UTC+5) in `src/lib/format.ts`.

## Folders

```
src/
  api/            request layer, error codes, generated client, our hooks
  app/            routes, providers, query client
  components/     shared components; ui/ holds the shadcn/ui primitives
  i18n/           language choice and the kk / ru / en texts
  lib/            formatting, form helpers, environment
  pages/          pages (placeholders until their phase), dev/ui page
  styles/         design tokens
  test/           test setup, MSW server, render helpers
e2e/              Playwright tests
```
