# Requirements traceability: SRS → web screen → test

This file answers one question for the web application: **for every required SRS requirement, what did we build, how is it tested, and what is missing?** It is the base for the "requirements → results" table of the report.

- **Specification:** BiletFlow SRS, version 0.3 ("Initial Draft"). Section numbers below are the SRS's.
- **Code version:** `main` at `5878d90` (phases W1–W12 merged) plus the W14/W15 changes of branch `web/w15-evidence`. The final commit or tag is named in the report and in [`DEMO.md`](DEMO.md).
- **Scope of this file:** the web frontend in `web/`. Backend behaviour is listed only where a web test observes it. The backend has its own end-to-end tests (`backend/tests/e2e`, not part of this file).
- **What this file does not know:** work that is not in `web/` or not visible in this repository's git history (the mobile scanning app, design, the backend team's own tests, anything done outside git) is described here only as far as the web observes it. The team must add its own evidence for those parts in the report.
- **Written:** 2026-11-26, from the repository, the tests and the runs described in "How the evidence was produced". Nothing here is taken from memory: where a test does not exist, the row says so.

## How to read the tables

**Status**

| Status                  | Meaning                                                                                                           |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **done**                | Built, and at least one automated test exercises the main behaviour.                                              |
| **partial**             | Built in part, **or** built but no test asserts the main behaviour. The last column says exactly what is missing. |
| **outside web**         | Belongs to the backend or the mobile app. Where a web test observes it, the test is named.                        |
| **skipped by decision** | Deliberately not built (a bonus, or excluded by SRS §8).                                                          |

**Test kinds** (paths are relative to `web/`; unit tests live next to the code, so `organizer/EventPage.test.tsx` means `src/pages/organizer/EventPage.test.tsx`)

- _unit_: Vitest, jsdom, API mocked with MSW. 445 tests in 45 files.
- _stub_: Playwright in Chrome, the API replaced by stubs inside the test. Runs without a backend.
- _live_: Playwright in Chrome against the **real backend and a real PostgreSQL database** filled by `backend/scripts/seed_demo.py`. These tests skip themselves unless their `BILETFLOW_E2E_LIVE_*` variable is set. 67 Playwright tests in 17 files in total (`npx playwright test --list`).
- _Manual_: no human manual test session is recorded for this submission. The column lists only checks made by hand during W15 (looking at the demo screenshots in `demo-recordings/`, which are outside the repository).

**Wording:** "not verified" means no test and no manual check covers it. It does not mean it is broken.
